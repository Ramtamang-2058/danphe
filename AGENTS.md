# AGENTS.md

## What this is
Danphe: a Python 3.11+ agentic dev CLI (NVIDIA NIM / Groq backends) plus a Playwright-based social-media automation layer (Instagram/WhatsApp). No tests, no CI, no linter config — verify by running `danphe` directly.

## Running it
- `danphe` resolves to an **editable install** of this repo (`pip install -e .`, entry `danphe.cli:main`), so code changes take effect without reinstalling. A separate `venv/` also exists; the system install is what the `danphe` command uses.
- `danphe` → interactive REPL; `danphe ask "…"` streaming Q&A; `danphe run "task"` agentic tool loop (`--max-iter`, default 10); `danphe models` shows routing; `danphe social <platform> <target> [--auto-reply]`.
- REPL slash commands: `/model`, `/compact`, `/instagram`, `/skills`, `/add`, `/help`.

## Config / env
- `.env` is loaded in order from: cwd, `~/.danphe/.env`, repo root (`danphe/config.py`). Keys: `NVIDIA_API_KEY`, `GROQ_API_KEY`, `DANPHE_MODEL` (`fast|long|reasoning|groq|auto`), `DANPHE_MAX_TOKENS` (default 16384), `DANPHE_DEBUG=1` (also prints reasoning tokens). See `.env.example`.
- `CLAUDE.md` (this repo) is read at runtime and injected into the agent system prompt (`config.load_claude_md`) — editing it changes danphe's own agent behavior, not just external tooling.

## Model routing (`danphe/router.py`)
- Auto priority: **Groq** (llama-3.3-70b, small convos only) → **NVIDIA** `fast` (z-ai/glm-5.2, <6K) → `long` (deepseek-ai/deepseek-v4-flash, <60K) → `reasoning` (nemotron-3-super) → devloop bridge. NVIDIA fast/reasoning tiers send thinking-mode `extra_body`. Groq is wired into the agent loop (`agent.py`) with full tool-calling; all providers retry rate-limit errors with exponential backoff (`danphe/llm/retry.py`) and use lower temperature (0.3 with tools, 0.7 for plain streams).
- **Groq TPM cap:** the on_demand tier counts `max_tokens` + input toward a ~12K TPM budget, so `groq.py` caps output at 6144 and `router.py` only routes small conversations to Groq (`GROQ_BUDGET`). The agent re-picks the backend **each iteration**, so as tool history grows mid-loop it auto-escapes to NVIDIA instead of 413-ing.
- **Circuit breaker:** when a backend 429s (daily quota exhausted — e.g. Groq TPD), `router.block()` marks it unavailable and the agent loop re-picks to the next healthy backend instead of 429-ing forever. Transient per-minute blocks expire after 90s; daily-quota blocks last the session (`router.blocked()`, `danphe models` lists them).
- **NVIDIA model IDs rotate:** check `danphe/llm/nvidia.py` `MODELS` against `https://integrate.api.nvidia.com/v1/models` — retired models return 410 (e.g. `z-ai/glm4.7` → `z-ai/glm-5.2`, `deepseek-v3-0324` → `deepseek-v4-flash`).

## Social automation
- `danphe social` and REPL `/instagram` are thin wrappers that subprocess `instra-automate/social_media.py` with **cwd = `instra-automate/`** (so sessions land there).
- Persistent Firefox profile at `instra-automate/browser_data/` (gitignored); needs `playwright` + `playwright install firefox`. Browsers are cached in `~/.cache/ms-playwright/`.
- Replies are generated by `danphe/social_agent.py` (`ReplyGenerator`): `auto` = Groq → NVIDIA fast, `max_tokens=300`. Default persona is "Ram" — human-sounding, mirrors the other person's language/tone, keeps replies to 1–2 sentences, never reveals being an AI.
- `~/.danphe/instagram_contacts.json` maps display names → @usernames for `/instagram` target resolution; skills live in `~/.danphe/skills/*.md` (exposed via `list_skills`/`read_skill` tools).

## IPO automation (native skill)
- `danphe/ipo.py` + the `ipo_*` tools (`ipo_status/login/check/apply/submit/close`) let the agent apply for MeroShare IPOs itself via a persistent visible Firefox profile at `~/.danphe/ipo-browser/` — no external script.
- Credentials/members are read in place from `/home/ram/Documents/Projects/meroshare-ipo-applier/config/` (separate repo — read-only; results append to its `applications_log.csv`).
- `ipo_login` prompts for the master password on the terminal via `getpass` (never via tool args/chat); `ipo_apply` pauses for the user to solve the CAPTCHA, then `ipo_submit` completes. Requires the `cryptography` and `playwright` (firefox) deps.

## Gotchas
- `requirements.txt` is a full `pip freeze` dump (system packages) — **not** a manifest. Real deps: `pyproject.toml` `dependencies` + `social_requirements.txt` (playwright==1.40.0).
- Two tool layers exist: `danphe/tools.py` (`SCHEMAS` + `execute` — what the agent loop uses) and the top-level `tools/` package (`read_files`/`shell_tool` helpers used for `-f` file attachment). Don't confuse them.
- The `write_file` tool auto-creates parent dirs and writes a `.bak` before overwriting; `read_file` caps at 100 KB (`config.MAX_FILE_KB`).
- `danphe/patches.py` (`# FILE: path` patch format ported from devloop) is legacy/unused — the agent loop applies edits via tool calls, not patches.
- Streaming is deliberately resilient: mid-stream network errors surface as inline `[Stream error]` text instead of crashing, and already-executed tool results persist even when the stream breaks.
- Standalone variants live at repo root: `continuous_social_automation.py`, `demo_social_automation.py` — older versions of the social layer.
